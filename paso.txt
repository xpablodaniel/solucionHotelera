Próximo paso: conectar Rooming + configuración de camas

La idea será enriquecer cada habitación del Rooming:

238
│
├── Inventario
│   ├── código: XI
│   ├── tipo: TRIPLE MATRIMONIAL
│   └── capacidad: 3

├── Pasajeros

│   ├── pasajero 2
│   └── pasajero 3
│
└── Configuración física
    ├── 1 matrimonial
    └── 1 individual

Pero todavía sin asignar personas a camas.

El resultado buscado

Agregaríamos algo como:

{
    numero: "238",

    capacidad: 3,

    cantidadPasajeros: 3,

    ocupacion: {
        plazasLibres: 0,
        porcentaje: 100,
        estado: "OK"
    },

    inventario: {
        codigoTipo: "XI",
        tipo: "TRIPLE MATRIMONIAL",
        capacidad: 3
    },

    configuracionCamas: {
        codigoTipo: "XI",
        camas: [
            {
                tipo: "MATRIMONIAL",
                cantidad: 1
            },
            {
                tipo: "INDIVIDUAL",
                cantidad: 1
            }
        ]
    },

    pasajeros: [...]
}
🔑 Y acá aparece una separación fundamental

Vamos a tener tres conceptos diferentes:

1. Lo que tiene físicamente el hotel

XI
1 matrimonial + 1 individual

2. Cuántas personas vienen en la reserva

3 pasajeros

3. Cómo finalmente distribuimos esas personas

Matrimonial → pasajero A + pasajero B
Individual  → pasajero C

El punto 3 todavía NO lo hacemos.

Eso nos permite manejar correctamente casos como:

Cuádruple
1 pasajero

sin que el programa diga:

"Hay tres camas libres, voy a cambiarlo de habitación."

No. La habitación contratada/asignada sigue siendo válida.

🧪 La próxima prueba

Vamos a crear una función pequeña, probablemente:

getBedConfiguration(codigoTipo)

y otra capa:

attachBedConfiguration(rooming)

La segunda solamente hará:

Rooming
   ↓
lee codigoTipo
   ↓
consulta catálogo
   ↓
agrega configuracionCamas

Sin modificar pasajeros ni asignaciones.
